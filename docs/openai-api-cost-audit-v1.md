# OpenAI API Cost Audit V1

**Audit base:** `test@65b9fb531dc250d56aed3e3cd72ea747ebe9989c`

**Audit branch:** `cloud/openai-cost-audit-v1`
**Scope:** the stable backend at this commit. Research Pipeline V2 and Visual Quality & Diversity V1 were not read or modified as development branches. This is a report-only change.

## Executive finding

The recent increase is best explained by repeated end-to-end development generations, not by Topic Intelligence. The local database contains 25 projects; 20 are repeated runs of the four recent visual-regression topics (Mars 8, Berlin Wall 4, fridge 4, chewing gum 4). Those runs recorded 50 billed image generations and 61 image attempts. At the measured normal request shape, 20 end-to-end runs plausibly represent roughly **$2.40-$4.80** of API usage before retry variance. This range is consistent with, but cannot prove, the reported roughly EUR 4 weekly increase because ClipForge does not record general Responses, TTS, or cached-token usage.

Topic Intelligence is comparatively small. Its stored telemetry records 55 semantic-curation requests, with token details on 42 batches: 98,200 input tokens, 74,480 output tokens, and 11,101 reasoning tokens. At current GPT-5.6 Luna list rates, the recorded portion is about **$0.109**. Thirteen request records lack batch token data, so this is incomplete, but it is far below the repeated video-generation estimate.

The production pipeline also contains real cost multipliers:

1. A content-readiness retry rebuilds the entire initial state once, repeating director planning, script writing, script review, hook generation, and hook judging.
2. Hook generation has one application-level retry for truncated structured output.
3. Most clients retain the OpenAI Python SDK default of two transport retries, allowing up to three HTTP attempts per logical call.
4. The director generates prose and hook material later regenerated by dedicated script and hook stages.
5. Script Review V2 is followed by another AI review before rendering. For V2-owned narration, the latter cannot apply its corrected body script.
6. Simple social, music, overlay, translation, and edit tasks silently use the GPT-5.6 default `medium` reasoning because they omit the reasoning setting.

## Method and limits

The inventory traces direct OpenAI client construction, Responses API calls, structured-output calls, image generation, speech generation, model settings, retry loops, job handlers, and UI polling entry points. Prompt sizes were estimated from the actual prompt builders and the 25 stored projects using characters divided by four. They are useful for comparison, not billing-grade token counts.

Official pricing and behavior used here:

- [GPT-5.6 Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra): $2/M input, $0.20/M cached input, $12/M output; `medium` is the default reasoning effort.
- [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna): $0.20/M input, $0.02/M cached input, $1.20/M output; `medium` is the default reasoning effort.
- [GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol): $4/M input, $0.40/M cached input, $20/M output; `medium` is the default reasoning effort.
- [GPT-4o mini TTS](https://developers.openai.com/api/docs/models/gpt-4o-mini-tts): $0.60/M text input and $12/M audio output.
- [Image generation](https://developers.openai.com/api/docs/guides/image-generation): GPT Image 2 low-quality 1024x1536 output is estimated at $0.005 per image, plus text/image input tokens.
- [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching): caching is automatic on supported models; cache hits require an identical stable prefix and become available at 1,024 input tokens.
- [Python SDK retries](https://developers.openai.com/api/reference/python): connection errors, 408, 409, 429, and 5xx responses are retried twice by default.

ClipForge currently lacks central usage telemetry for normal generation. Consequently, actual output tokens, reasoning tokens, cached tokens, transport retries, and request costs for normal videos are **unknown**. Cost ranges below are estimates, not reconstructed invoices.

## One normal video, stage by stage

The fixed normal path contains nine logical OpenAI requests:

1. Director plan.
2. Script Writer V2.
3. Script Review V2.
4. Hook generation.
5. Hook judge.
6. Music ranking.
7. Pre-render AI review.
8. TTS.
9. Social metadata.

Variable work adds `O + T + I`, where `O` is distinct overlay summaries, `T` is distinct visual translations, and `I` is AI image requests. Stored projects show means of 0.76 overlay summaries, 3.4 translations, and 2 successful images. A representative normal video therefore makes about **15 logical OpenAI requests**.

| Entry path | Minimum | Typical cold path | Practical application-level maximum | Notes |
|---|---:|---:|---:|---|
| Manual question | 9 | 15 | about 34 | Maximum includes one full initial-state retry, hook truncation on both passes, up to seven overlays, seven translations, three successful images, two review passes, TTS, music, and social metadata |
| Assisted Topic Intelligence | 9 | about 18 | about 38 | A warm/cached topic pool adds zero; a cold pool normally adds three curator calls and can widen to four |
| Full Auto | 9 | 18-19 | about 38 | Same pool mechanics; curator cost is amortized across topics/videos rather than intrinsic to each render |

The numeric maximum is not absolute. The three-image project cap counts successful/billed images, while non-blocking failed image attempts are bounded per scene. More scenes can therefore add rejected image requests. In addition, default SDK retries can turn one logical request into three HTTP requests. Under stacked full retries, the roughly 34-call application path could approach roughly 68 transport attempts; that is a pathological ceiling, not expected behavior.

No AI request is triggered by normal UI polling. Generation jobs are claimed once, preventing competing workers from processing the same job. Each explicit generation POST creates a new job, however; there is no cross-request hash that deduplicates two separately submitted identical projects.

|---|---:|---:|---:|---|
| Director | 3.3k tokens | 2.5k | 5.9k | Research facts, story context, hook playbook |
| Script Writer | 1.3k | 2.1k | 3.4k | Facts and story arc already seen by director |

| Pre-render review | roughly 1k+ | 5.1k | 6k+ | Facts, script, scenes, and the full triple-hook diagnostics |

Typical persisted object sizes are about 913 tokens for facts, 1,352 for the story arc, 2,127 for triple-hook state, 1,215 for hook-selection candidates, and 1,665 for visual intents. The complete final project state averages roughly 87.6k character-estimated tokens, but no normal generation call sends that whole object. The problem is repeated overlapping slices, not wholesale state transmission.

Output and reasoning exposure is highest on Terra calls. Director, writer, and social metadata have no application output limit. Medium reasoning is implicit on every GPT-5.6 call that omits `reasoning`, and reasoning tokens are billed as output. Without usage telemetry, the exact hidden reasoning contribution is unknown.

## Prompt-caching audit

Stable system instructions and schemas generally precede dynamic user content, so several calls are naturally eligible for automatic prefix caching. There is no cache-key configuration or telemetry proving cache hits.

The clearest cache-defeating construction is hook generation: stable `hook_playbook` and `document_strategies` are placed late in the dynamic JSON after project-specific prompt, body, story, and facts. Director planning similarly places stable playbook material after dynamic fields. Moving stable playbooks into the stable prefix, before project content, would increase reusable prefix length without changing model-visible information.

Core prompts do not insert timestamps or random IDs before their stable instructions. Topic batches use changing topic payloads and compact per-batch IDs, so large cross-batch cache hits are less likely. ClipForge does not record `usage.input_tokens_details.cached_tokens` or cache-write token details, so current cache effectiveness cannot be quantified.

## Model-routing and reasoning assessment

**High-intelligence required:** director planning and Script Writer V2. Their Terra/medium route is defensible. Hook generation is quality-sensitive and already uses low reasoning. Hook judging is quality-sensitive enough that a change should be evaluation-led.

**Medium:** Script Review V2 and pre-render review. Luna is appropriate; medium reasoning may be more than needed, but quality should be measured before lowering it. The duplication between these reviews is a stronger optimization target than a blind model downgrade.

**Cheap or deterministic possible:** social metadata, music ranking, overlay summary, visual translation, direct editing, and routine editor decisions. Social metadata is the clearest mismatch because it uses Terra with implicit medium reasoning and no output cap. Music already has deterministic ranking. Overlay and translation are short transformations but pay for medium reasoning. Direct editing has a deterministic fallback.

Explicit reasoning configuration exists only for hook generation (`low`) and Topic Intelligence (`low`). All of the following inherit `medium`: director, writer, script review, hook judge, music, pre-render review, social metadata, overlay summary, visual translation, direct edit, and editor agent. Medium is justified for director/writer and potentially the judges; it is not justified for formatting, short extraction, music selection, or social copy.

## Unnecessary or duplicated work

1. The director produces body script and hook material that dedicated writer and hook stages later regenerate. Some planner content remains useful for story and visual intent, and one planner hook competes in the final set, so removal needs an evaluation-backed contract change rather than deletion by assumption.
2. Script Review V2 and pre-render AI review both evaluate the script. For V2-owned narration, pre-render corrected body text is discarded, making that portion advisory-only.
3. Music selection calls Luna after deterministic ranking already supplies an ordered candidate set.
4. Social metadata uses Terra even though a deterministic fallback already exists.
5. The same facts and story information are sent to director, writer, script review, hook generation, and pre-render review.
6. Visual translation averages 3.4 calls/project while successful AI images average 2. Some translations are computed for fallback paths that do not result in an image.
7. Separate explicit generations of the same question are not deduplicated. This is appropriate for intentional regression testing but directly explains development spend.
8. UI polling does not retrigger AI. There is no evidence of accidental polling-based generation.

## Existing telemetry

Topic Intelligence stores model, request count, input tokens, output tokens, and reasoning tokens for some batches. Image-generation diagnostics store attempts and whether an image was billed. Project state preserves some AI-stage outputs and hashes.

There is no central record for normal text/TTS calls containing model, stage, project ID, request ID, retry number, input tokens, cached input tokens, output tokens, reasoning tokens, latency, or estimated cost. Failed transport attempts are also not attributable. As a result, exact per-project cost and the split between reasoning and visible output cannot be reconstructed.

The smallest reliable telemetry layer is one central recorder around OpenAI calls. It should accept `stage`, `project_id`, and logical `attempt`; persist the response request ID, model, usage fields (including cached and reasoning tokens where exposed), status, and latency; and calculate cost from a versioned price table outside business logic. It should never store prompts or API keys. Existing Topic Intelligence and image-attempt records can feed the same event schema later. This audit does not implement it because central instrumentation would touch many production call sites and the requested task is primarily an audit.

## Cost estimate per video

The following ranges use current public USD list prices, measured prompt sizes, and plausible output/reasoning ranges. Currency conversion, Batch API discounts, cached-token hits, and unobserved retries are excluded.

| Path | Known | Estimated normal range | Retry-heavy range | Unknown |
|---|---|---:|---:|---|
| Manual question | Nine fixed calls; observed variable-call distributions | **$0.12-$0.24** typical; about **$0.09-$0.16** for a low-output/no-image success | **$0.25-$0.55+** with whole-state/hook retry; transport retries can exceed this | Actual output/reasoning/cached tokens |
| Assisted Topic Intelligence | Same video path; cold pool usually adds three curator calls | **$0.13-$0.25** cold; warm pool equals manual | About **$0.26-$0.56+** with four curator calls and generation retries | Pool cost allocation across resulting videos |
| Full Auto | Same video path; cold pool can widen from three to four calls | **$0.13-$0.26** cold; warm pool equals manual | About **$0.26-$0.56+** | Same telemetry gaps |

A recent ten-topic Luna curator batch costs roughly $0.0028-$0.0031 using stored token counts. Three cold-pool calls add around one cent and can be amortized across multiple topics. Topic Intelligence therefore does not explain multi-euro weekly growth by itself.

For orientation, a 30-second TTS output is approximately $0.0072 using the documented audio-token conversion and list price. Two typical low-quality portrait images contribute about $0.01 plus prompt input. Terra text output is the dominant unit price: planning, writing, and hook generation/judging are therefore the main recurring cost center.

| Rank | Change | Expected saving | Quality risk | Effort |
|---:|---|---|---|---|
| 1 | Make the director contract planning-only after golden-project evaluation: retain facts/story/visual intent, stop producing body prose and redundant hook output that dedicated stages regenerate | High; likely saves Terra output/reasoning and reduces downstream prompt duplication, approximately $0.01-$0.04/video depending on output | Medium until validated against story/hook quality | Medium |
| 2 | Route social metadata from Terra/medium to Luna with `none` or `low` reasoning and a strict output cap; retain its deterministic fallback | Medium relative to one unconditional simple call; roughly 90%+ model-rate reduction for this stage | Low | Low |
| 3 | Skip the script-correction portion of pre-render AI review when Script Review V2 already approved and owns narration, while retaining deterministic visual/media gates | Low-medium; removes or shrinks one Luna call and about 6k input tokens | Low if scoped to V2-owned narration and regression-tested | Medium |
| 4 | Set `none`/`low` explicitly for music, overlay, translation, and direct edit; make music deterministic when its top score is decisive | Low-medium in aggregate; prevents hidden reasoning tokens on frequent simple calls | Low | Low |
| 5 | Move stable hook playbook/document strategies ahead of dynamic project content and record cache hits | Medium during repeated development runs; up to a 90% input-rate reduction on the newly cacheable prefix after a cache hit | Very low | Low |

Before changing the quality-sensitive director contract, add central usage telemetry and a small golden-project comparison. The **first immediate cost change** should be the social-metadata route: Luna with explicit low/none reasoning and a bounded output. It is unconditional, simple, covered by a deterministic fallback, and currently pays Terra's much higher input/output rates plus implicit medium reasoning.

## Development versus production

Normal production will usually reuse one topic-pool curation across several topic choices and generate a project once. Development repeatedly generated identical questions to validate media selection and fallback changes. The 20 repeated regression projects, 50 billed images, repeated TTS outputs, and repeated Terra planning/script/hook calls are sufficient to make development the likely majority of the recent increase.

The estimate of $2.40-$4.80 for those 20 normal-shaped generations overlaps the observed spend increase. This is an inference from code, stored run counts, and list prices, not billing attribution. Whole-state retries, SDK retries, cached inputs, output/reasoning length, failed generations, voice previews, and editor usage can move the result materially. Central usage events are required to replace this range with exact per-stage and per-project numbers.
