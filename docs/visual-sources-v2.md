## Rights evidence

No provider identity grants reuse. Openverse's [license accuracy caution](https://docs.openverse.org/api/reference/made_with_ov.html) applies: credits persist the aggregator assertion and original source; an asserted CC license is not independent legal verification. Exact CC URI normalization reuses the foundation authority. Conflicting IDs/URIs, NC/ND/SA, ambiguous Europeana rights and RightsStatements identifiers fail closed. Attribution survives candidate/schema/scene/revision/manifest and includes transformation notice.

NASA's [usage guidelines](https://www.nasa.gov/nasa-brand-center/images-and-media/) warn about third-party material. Its [actual item metadata example](https://images-assets.nasa.gov/image/as11-40-5874/metadata.json) contains item XMP fields. [Adobe defines Marked=false as public domain, omission as unknown](https://developer.adobe.com/xmp/docs/xmp-namespaces/xmp-rights/). Only a boolean false paired with matching `AVAIL:NASAID` establishes PD; conflicting rights text blocks it. NASA credit is retained. No blanket NASA permission, filename/date inference, or conversion of missing copyright into permission.

LOC accepts only explicit affirmative item public-domain statements; “no known restrictions” is insufficient. Missing statements stay unknown. Conservative exclusions can reduce coverage; widening and the existing AI/reuse/graphic chain remain the remedy.

## Bounds and cache

Two relevant providers form the primary pool; coverage is evaluated with the existing deterministic relevance, OpenCLIP shortlist and quality gate before widening. Suitability changes discovery order, never acceptance. Three logical queries, 18 physical search/detail/manifest requests, 72 verification admissions, and 12 preview/download operations remain shared per acquisition. Image dimension probes read at most 512 KiB, at most three per provider search; selected files at most 30 MiB. Unknown dimensions are never invented.

Metadata-only process cache: 128 entries, five-minute TTL, provider/normalized query/kind/public parameters key, no headers/credentials/raw envelopes, deep copies, only rights-usable candidates. Every cache admission/selection/Apply/reuse rechecks rights. Original page/media keys handle aggregator and Commons thumbnail/original duplication. No perceptual hashing.

[Openverse official throttling defaults](https://github.com/WordPress/openverse/blob/main/api/conf/settings/rest_framework.py) currently specify anonymous 5/hour and 100/day; deployment limits can differ. A conservative nonblocking hourly limiter avoids repeated requests; server 429/Retry-After remains authoritative. LOC uses its documented 20/minute. Missing Europeana key skips Europeana only. The existing Settings card and OS keyring support `EUROPEANA_API_KEY`; no settings are required for anonymous sources.

Scene `media_search.stages` records routing reasons/tiers, actual provider work,
candidate and rejection counts, cache hits, verification admissions, widening,
coverage and failures. Existing winner/fallback records and render diagnostics
retain source identity and accepted evidence, without secrets.

LOC searches digitized images across formats, including photographic maps when eligible. Download failures after strong primary coverage trigger bounded widening of only already executed query strings, skipping previously attempted provider/kind pairs.

## Phase 1 retrieval fixes (2026-10-09)

Commons and NASA were already registered sources; this phase fixes how they contribute. No new provider, credential, paid call or production default flag.

- **Commons search rank.** `generator=search` returns `query.pages` keyed by page id; the per-page `index` is the search rank. Candidates were previously ranked by page-id order. They now follow `index`.
- **Commons dimensions.** Superseded by the live-validation repair below: the API's `thumbwidth`/`thumbheight` do not describe the delivered file.
- **Commons zero-hit queries.** CirrusSearch matches all words, so long scene queries often returned nothing (all four Mars-audit scenes: `wikimedia returned=0`). After a zero-hit strict search, one `a OR b OR …` request over at most six content words is allowed only while at least four shared search requests remain; it is counted in the acquisition budget and recorded as `origin.search_mode=any_keyword`. Relevance, OpenCLIP and rights gates are unchanged.
- **Commons failures.** HTTP 429 and MediaWiki `ratelimited`/`maxlag` error envelopes set a per-client, nonblocking cooldown (Retry-After, bounded 30–600 s). Other HTTP-200 `error` envelopes are `provider_error`, never an empty search; HTTP 5xx is `provider_error`. The User-Agent now carries a contact URL per Wikimedia policy.
- **NASA ↔ Commons mirrors.** NASA candidates carry `origin.canonical_id` (the NASA ID). A Commons file whose credit/description links `images.nasa.gov/details/<id>` or whose title/credit names a JPL `PIA#####` ID records `origin.same_as=[{"provider": "NASA", "canonical_id": …}]`; `asset_keys` treats both as one asset for in-scene and cross-scene dedupe. No other identity is inferred.
- **Normalized metadata.** `asset_metadata(candidate)` (persisted in candidate evidence and `SceneMediaCandidateRead.asset_metadata`) reports source, source/media/preview URL, asset type, dimensions (`known=false` when absent), license id/name/url/flags with the rights authority's status and reason, attribution and `usage_restrictions`. Restrictions are descriptive only: uncleared rights are listed as `not_cleared:<reason>`, Commons `Restrictions` values (`commons:trademarked`, …), attribution/share-alike/NC/ND obligations, and provider-wide grants as `provider_prohibited_uses_apply` / `third_party_rights_not_cleared`. Routed stage diagnostics include `license_id`, `usage_restrictions` and dimensions per candidate.

Not verified live from the build sandbox (Commons/NASA hosts were unreachable); the any-keyword `OR` syntax and `index` field follow the MediaWiki/CirrusSearch API contract and should be confirmed on the first real run via `diagnostics/visual-acquisition.json` (`search_mode`, per-provider `returned`).


## Live-validation repairs (2026-10-10)

The first real Commons/NASA run (30 requests; every response HTTP 200) found four defects, all reproduced from its JSON report.

- **Commons delivered size.** Requesting `iiurlwidth=1600` does not deliver 1600 px: when the original is smaller Wikimedia serves it unscaled (`...?utm_content=thumbnail_unscaled`, e.g. 1287x1425 reported as 1600x1772), and for large originals it serves a standard 1920 px thumbnail from `thumb.wikimedia.org`. `commons_delivered_size` derives the delivered size from the validated original size and the actual URL (`original`, `original_unscaled`, `thumb_url` = `<N>px-` scaled from the original, `thumb_url_capped`); an unexpected URL shape assumes no more than the API's thumbnail size capped at the original (`api_thumb_capped`), and an unknown original assumes nothing (the candidate is dropped by the 640 px floor). API values stay in `origin.api_thumb_*` / `original_*`, the rule used in `origin.dimension_source`. An undersized original (a 1024x513 panorama had been admitted as 1600x802) no longer passes the floor.
- **Decoded size is authoritative after download.** `delivered_photo` reads the cached file's real pixel size; scene media evidence carries it as `width`/`height` with `delivered_dimensions = {width, height, source: "decoded", reported}`. A decoded short side below the shared 480 px floor removes the file and fails the candidate (`undersized_media`) so the next one is used. A file Pillow cannot identify keeps the provider size. Applies to every photo provider (Pexels portrait/landscape renditions are now measured too); video is unchanged.
- **Wikimedia deduplication.** `canonical_source` treats `thumb.wikimedia.org` like `upload.wikimedia.org`, so originals, unscaled, 320/1600/1920 px thumbnails, Special:FilePath and the file page share one identity.
- **NASA is a fallback source (temporary).** Live, the top NASA items carried only `AVAIL:NASAID` (no `XMP:Marked`, no rights text), so none was cleared while each query spent about 7 of the shared 18 requests. Space/earth-observation scenes now route Wikimedia and Openverse first; NASA leads the second tier and is queried only when their coverage is not strong (or on download recovery). NASA can never share the first tier, even if a leading source is unavailable. The NASA rights policy is unchanged: no item is cleared without the boolean `XMP:Marked=false` plus a matching `AVAIL:NASAID` and no conflicting rights text.
- **NASA enrichment diagnostics.** Each candidate's rights evidence adds `rights_fields_present` / `rights_fields_missing` (field names only) and `enrichment` = `{metadata, asset_manifest}` with `fetched`, `location_rejected`, `error:<category>`, `not_attempted:beyond_enrichment_limit | budget_headroom | no_nasa_id` and `original_found | no_original_image | not_needed`. Raw values are not copied.
- **Creative Commons recognition.** `License: "cc0"` is recognised as CC0, and a trailing `/deed` or `/deed.<language>[-<region>]` on the exact creativecommons.org host is ignored (`.../4.0/deed.de`). `cc0`/`cc-zero` with a license URL that is not the CC0 path (spoofed host, other license) is conflicting evidence and stays unknown. CC BY-SA, NC and ND stay blocked; unknown or conflicting evidence stays unknown.
- **Live script.** `scripts/visual_sources_live_check.py` compares each probed file with the delivered-size rule (1 px tolerance; only a *reported size larger than delivered* fails), reports probe failures separately, no longer requires a rights-usable NASA image (coverage is printed), checks that NASA trails Wikimedia and is not queried while the first tier is strong, and forces the fallback tier for its NASA-timeout scenario.
